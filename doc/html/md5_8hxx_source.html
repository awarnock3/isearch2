12// BUGFIX #1: uint32 was typedef'd from `unsigned long`, which is 64
13// bits wide on any LP64 platform (every 64-bit Unix/Linux target this
14// tree builds on today) -- not actually 32 bits as MD5's bit-rotation
15// arithmetic and MD5Transform's `(uint32*)ctx->in` 16-word cast both
16// require. The __alpha special case was a 1990s-era guess at which
17// platforms had a 32-bit long; it's no longer a reliable signal on
18// modern 64-bit systems, Alpha or otherwise. Confirmed real: on this
19// platform sizeof(uint32) was 8, and a standalone repro of
20// MD5Init/MD5Update/MD5Final crashed under ASan with a stack-buffer-
21// overflow in MD5Transform (the 16-word cast over ctx->in reads/writes
22// 128 bytes into a 64-byte buffer once each "word" is 8 bytes instead
23// of 4). Fixed by using the real fixed-width type. See
24// docs/BUG_CATALOG.md#srcmd5hxx.
25typedef uint32_t uint32;

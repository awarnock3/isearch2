# CNIDR Isearch-cgi 2.00

*02 August 2026*

## Overview

Isearch-cgi is a set of utilities that, used in conjunction with CNIDR's
Isearch search engine, provides full text and fielded search capability via
the World Wide Web.

## Installation

1. Install a CGI-compliant HTTP server.

   Apache is recommended, but any CGI-compliant server will suffice.

2. Retrieve, compile, and install the latest version of CNIDR Isearch.

   Isearch2 is available at:

   <https://github.com/awarnock3/isearch2.git>

   You must successfully compile Isearch before compiling Isearch-cgi.

   This Makefile will attempt to compile Isearch for you if you haven't
   already done so.

3. Build the distribution.

   Run:

   ```bash
   make
   ```

   If all goes well, four binaries should be created in the `Isearch-cgi`
   directory:

   - `isrch_fetch`
   - `isrch_srch`
   - `isrch_html`
   - `isrch_api`
   - `search_form`

4. Install the Isearch-cgi scripts.

   There are four shell scripts, one for each cgi-bin utility, that must be
   configured and then installed in the cgi-bin directory as well:

   - `ifetch`
   - `isearch`
   - `ihtml`
   - `isearch_api`

   Isearch-cgi includes a script that will produce these files for you. The
   script's name is `Configure` and it requires a single argument: the path to
   your databases.

   ```bash
   ./Configure /absolute/path/to/databases
   ```

   After `Configure` is run, the files it produces can be edited by hand, if
   needed.

## Configuration of Isearch-cgi

1. Build a database.

   Use `Iindex` to build a sample database. To see the full features of
   Isearch-cgi, index a small collection of HTML files, preferably a
   collection that is marked up well (with explicit `title`, `body`, etc.).

   For this example, build a database called `TEST` that resides in
   `/usr/dbs`:

   ```bash
   Iindex -d /usr/dbs/TEST -t SGMLTAG /htdocs/*.html
   ```

2. Configure scripts.

   The only configuration required by Isearch-cgi takes place in the
   `Makefile` and scripts: `ifetch`, `isearch`, `ihtml`, and `isearch_api`.

   Edit those files (or run `Configure`) and answer the questions.

3. API environment variables.

   The `isrch_api` endpoint runner reads these optional environment variables:

   - `ISEARCH_DB_PATH` - base directory containing Isearch database roots
   - `ISEARCH_API_MAX_HITS` - maximum allowed `max_hits` request value
   - `ISEARCH_API_ALLOWLIST` - comma-separated list of permitted database names

4. API CGI deployment example.

   Copy `isearch_api` into your CGI directory and route `/api/v1` to it. For
   Apache, one workable setup is:

   ```apacheconf
   ScriptAlias /api/v1 /usr/lib/cgi-bin/isearch_api
   <Location /api/v1>
     Options +ExecCGI
     SetEnv ISEARCH_DB_PATH /absolute/path/to/databases
     SetEnv ISEARCH_API_MAX_HITS 200
     SetEnv ISEARCH_API_ALLOWLIST XMLtest,MDtest
   </Location>
   ```

   The API runner accepts `PATH_INFO`, so requests such as
   `/api/v1/search?database=XMLtest&q=dust` are dispatched correctly.

## Operation of Isearch-cgi

1. Create access points to databases.

   Create a base HTML file with the `search_form` program. It takes two
   arguments: the path to your databases, and the name of the database this
   page should access. The page is printed to standard output.

   ```bash
   search_form /home/databases TEST > form.html
   ```

   There is another optional argument that indicates which type of search page
   to generate. The form types are:

   - `-simple`
   - `-boolean`
   - `-advanced`
   - `-html`

   If no type is given to `search_form`, it defaults to `-simple`.

   Examples:

   ```bash
   search_form -simple /home/databases TEST > form.html
   search_form -boolean /home/databases TEST > boolean.html
   search_form -advanced /home/databases TEST > advanced.html
   search_form -html /home/databases TEST > htmlform.html
   ```

2. Load the form and search.

   Running `search_form` generates a search page customized for the target
   database. Load it in a browser to perform fielded and full-text queries and
   retrieve portions of the resulting documents.

   The output is a base form; customize layout and design as needed.

3. Customizing HTML database searches.

   Isearch-cgi can return links directly to indexed HTML documents (instead of
   going through `isrch_fetch`) to preserve relative links.

   It checks whether the document lies within the HTTP document root. The
   document root location is passed through the HTTP server.

   `isrch_html` is designed for indexes of HTML files. Its script wrapper is
   `ihtml` (created by `Configure`). The search form generated by using
   `-html` with `search_form` calls `ihtml` instead of `isearch`. Headlines
   are returned as anchors to document URLs.

   If documents do not lie within the HTTP server tree (as defined by the
   `DOCUMENT_ROOT` environment variable), the program tries to provide a link
   via `ifetch`.

4. GET vs. POST methods.

   Both methods work, so GET can be used for canned queries. Example URL:

   ```text
   http://localhost/cgi-bin/isearch?DATABASE=TESTHTML&SEARCH_TYPE=boolean&FIELD_1=FULLTEXT&TERM_1=kevin&ELEMENT_SET=title&MAXHITS=10
   ```

## Changes

- Later - see the file `CHANGES` in the Isearch directory
- 1.04 - Various small patches to allow building under Windows NT and Win32.
  New `isrch_srch.cxx` main program.
- 1.03.02 - Removed obsolete `path` from `Search()` call. Now compiles.
- 1.03.01 - Isearch-cgi gets the HTTP document root from the environment.
- 1.03 - Renamed to 1.03 distribution.
- 1.02.07 - Fixed bug that caused errors in "Retrieve Next".
- 1.02.06 - `<head>` and `<body>` tags included to be gentler to some
  browsers (thanks to Archie Warnock).
  `isrch_srch`, `isrch_bool`, and `isrch_adv` all merged into `isrch_srch`.
  Shell scripts `ibool` and `iadv` removed.
  The `Configure` script now produces `isearch` and `ifetch` when the
  database path is given as a parameter.
  Shell scripts `isearch` and `ifetch` now point to the Isearch-cgi
  directory, where binaries reside.
  Actual binaries (`isrch_srch` and `isrch_fetch`) are no longer copied to
  cgi-bin.
  Fixed bug that restricted BOOLEAN search terms to 2 words.
- 1.02.05 - `isrch_srch`, `isrch_bool`, and `isrch_adv` use a shared
  `Search()` function to ease display-format changes.
  `isrch_bool` parses each argument in case a term is more than one word.
  Multiple-word queries for a single term are assumed to be OR terms.
  Added CGI variable `HTTP_PATH` to request direct page links instead of
  `isrch_fetch`.
  `isrch_fetch` now wraps non-HTML documents in `<pre></pre>` blocks for
  easier viewing.
- 1.02.04 - Tim Gemma takes over distribution and maintenance of Isearch-cgi.
  Fixed "Retrieve Next #" display.
  Renamed `isrch_form` to `search_form`.
  Added `ibool`/`isrch_bool` for boolean searching.
  Added `iadv`/`isrch_adv` for advanced INFIX searching.
  Incorporated `cgi.c` and `httpbox.c` into C++ class `CGIAPP` in
  `cgi-util.cxx`.
  Boolean search no longer crashes when only one term is passed.
- 1.02.03 - Changed all use of `STRING::Print()` to `operator<<`.
- 1.02.02 - Fixed bug in maximum number of hits code.
- 1.02.01 - Added CGI variables:
  - `START` - first result-set record to display in hit list
  - `MAXHITS` - max number of result-set records to display
  - `ISEARCH_TERM` - Isearch command-line query syntax, primarily used behind
    the scenes to fetch the next records
